# Issue contract: Use CRLF framing for multipart byte ranges

Implement every enumerated requirement. Preserve unrelated behavior and the public API unless a requirement explicitly changes it.

## R1 — Standards-compliant multipart framing

Multipart byte-range responses must use CRLF separators and produce parts that a standards-compliant multipart parser can consume.

## R2 — Exact lengths and terminal framing

Multipart byte-range body chunks, terminal boundary, and Content-Length must agree for GET, HEAD, reordered ranges, and small streaming chunks.
