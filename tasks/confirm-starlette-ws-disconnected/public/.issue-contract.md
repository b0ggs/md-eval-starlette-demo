# Issue contract: Distinguish disconnected WebSocket use

Implement every enumerated requirement. Preserve unrelated behavior and the public API unless a requirement explicitly changes it.

## R1 — Disconnected low-level operations have a dedicated error

Expose `WebSocketDisconnected` as a distinct `RuntimeError` subclass, and raise it with the existing messages when low-level receive or send is attempted after the corresponding WebSocket side has entered the disconnected state.

## R2 — Receive helpers report a disconnected application side

`receive_text()`, `receive_bytes()`, and `receive_json()` with a valid mode must raise `WebSocketDisconnected` when the application side is not connected; protocol-validation and invalid-mode failures must remain ordinary `RuntimeError` behavior, and peer disconnects must remain `WebSocketDisconnect`.
