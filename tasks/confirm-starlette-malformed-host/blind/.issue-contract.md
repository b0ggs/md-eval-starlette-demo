# Issue contract: Reject malformed Host authorities consistently

Implement every enumerated requirement. Preserve unrelated behavior and the public API unless a requirement explicitly changes it.

## R1 — Scope URLs validate authorities and fall back safely

When a URL is built from an ASGI scope, use a Host header only when its authority syntax is valid and its optional port is decimal and in the range 0 through 65535; otherwise fall back to the scope server and render IPv6 server addresses in brackets. Preserve valid zero-padded ports and lowercase IPvFuture literals.

## R2 — Host matching shares strict authority parsing

Host routes and TrustedHostMiddleware must reject malformed authorities and invalid IP literals, accept valid bracketed IPv6 and lowercase IPvFuture literals, and ignore a syntactically numeric port while matching, including zero-padded and out-of-range numeric ports.

## R3 — HTTPS redirects never emit malformed authorities

HTTPSRedirectMiddleware must fall back to a valid scope server when the Host header is malformed, bracket an IPv6 fallback authority, and strip default HTTP or HTTPS ports even when they are zero-padded; when neither a valid Host header nor a scope server exists, it must respond with status 400 and the body Invalid host header.
