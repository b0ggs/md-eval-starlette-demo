# Preserve streamed WebSocket denial responses

Starlette's ordinary responses can reject a WebSocket handshake, but response
classes with specialized call paths can emit HTTP-only events or read
HTTP-only scope fields. This breaks denial responses that stream content or
send files. Implement the upstream-compatible correction in this complete
Starlette checkout.

1. A `StreamingResponse` used as a WebSocket denial response must emit the complete body through valid WebSocket denial events, run its background task exactly once, and preserve its established HTTP behavior.
2. A `FileResponse` used as a WebSocket denial response must not assume HTTP-only scope fields or extensions, and must deliver the file body and status through valid WebSocket denial events.

Use the repository's real pytest framework for verification. Preserve the
public API and all unrelated behavior covered by the pre-existing response and
WebSocket tests.
